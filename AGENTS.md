# Duke Kunshan Signature Work Project

This repository contains my undergraduate Signature Work project.

## Project

I am developing a software-focused Creative/Design Signature Work involving:

- Agentic Retrieval-Augmented Generation (RAG)
- runtime evaluation
- failure diagnosis
- adaptive recovery
- recovery verification
- benchmarking
- trajectory/trace visualization

The central workflow is:

Agent acts
→ evaluation
→ failure diagnosis
→ recovery selection
→ recovery
→ verification
→ accept / retry / abstain

The project investigates whether evaluation can help an Agentic RAG system identify failures, choose appropriate corrective actions, and verify whether those actions actually improve the result.

The primary deliverable is working software.

## Academic Context

This is an academic Signature Work project.

Generative AI may be used as a supportive development tool, but the project's core intellectual contribution must remain mine.

I am responsible for independently understanding and deciding:

- project architecture
- problem framing
- Agentic RAG design
- failure taxonomy
- evaluation methodology
- recovery logic
- experimental design
- benchmark selection
- interpretation of results
- conclusions

Cursor may support:

- brainstorming
- technical explanations
- comparing implementation approaches
- debugging
- code completion
- boilerplate
- refactoring
- unit-test suggestions
- documentation
- identifying bugs and edge cases

For major intellectual decisions:

1. Explain the decision.
2. Present realistic alternatives.
3. Explain tradeoffs.
4. Give a recommendation if useful.
5. Ask me to confirm the decision before treating it as final.

Do not autonomously redesign or build the entire core project from a vague high-level instruction.

I should be able to explain and defend every important part of the final system.

## Engineering Principles

Prioritize:

- modularity
- understandable code
- reproducibility
- explicit interfaces
- traceability
- testing
- clean experiment configuration
- depth over feature count

Keep the AI/RAG core separate from the frontend.

Do not optimize for unnecessary complexity.

Do not add commercial SaaS features such as billing, enterprise authentication, or unrelated integrations unless explicitly requested.
